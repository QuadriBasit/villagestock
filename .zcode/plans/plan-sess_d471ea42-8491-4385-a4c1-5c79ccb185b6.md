## WhatsApp Phase 1: Send-to-WhatsApp for credits, receipts, and price lists

Manual buttons only, `wa.me` deep links with pre-filled message templates. No backend changes, no new dependencies.

### 1. New shared library: `src/lib/whatsapp.ts`
- `normalizePhone(raw: string): string | null` — strips spaces/dashes/parens, converts local Nigerian formats (`0803...`, `+234...`, `234...`) to MSISDN `234XXXXXXXXXX`; returns null if it can't produce a valid number (Nigerian: 10–11 digits after normalization). Non-234 numbers with a `+` prefix pass through.
- `openWhatsApp(phone: string, message: string)` — opens `https://wa.me/<msisdn>?text=<encoded>` in a new tab (`noopener,noreferrer`). If phone is null, falls back to `wa.me/?text=` (pick-a-chat, same as today's price-list button).
- `buildCreditReminderText(credit: CreditRecord, shop: ShopProfile)` — friendly template using `formatCurrency`/`formatDate` and WhatsApp `*bold*` markers (matching `priceListText.ts` conventions): greeting, item, total/paid/balance, due date (and "overdue by X days" when past due), shop name and thanks.
- `buildReceiptText(sale: SalesRecord, shop: ShopProfile)` — itemized line items, total, payment method, date, shop name/phone. (Text receipt for WhatsApp; PNG/PDF flow stays as-is.)

### 2. Credits: "Remind via WhatsApp"
In `src/pages/CreditsPage.tsx` → `CreditDetailsModal` footer, add a secondary outline button **"Remind via WhatsApp"** (green accent like the existing price-list button, `MessageCircle` icon), shown when `balance_owed > 0` and `customer_phone` exists. On tap: build reminder text → `openWhatsApp(customer_phone, text)` → `toast.success('Opening WhatsApp…')`. If phone missing/invalid: toast error "No valid phone number on this credit" and keep modal open.
Pull shop profile via existing `useShopProfile()` hook.

### 3. Sales: WhatsApp text receipt
- In `src/components/sales/SaleDetailModal.tsx` action grid: rename/extend the current "Send receipt" path — keep opening `ReceiptModal` (PNG/PDF) but add a separate small **"WhatsApp receipt"** outline button that calls `openWhatsApp(sale.customer_phone, buildReceiptText(...))` directly; falls back to pick-a-chat when there's no customer phone.
- In `ReceiptModal.tsx` footer, also add a WhatsApp button that shares the already-captured PNG via `navigator.share` when supported, else falls back to the text receipt deep link.

### 4. Price list: direct send
`src/pages/PriceListPage.tsx` — upgrade existing `shareWhatsApp` to accept an optional customer phone (small phone input next to the WhatsApp button, optional); keep the copy-to-clipboard behavior as a fallback.

### Conventions
- All new UI uses existing `Button`/`Input` from `src/components/ui/` (per CLAUDE.md rule — no raw HTML elements), `sonner` toasts, WhatsApp green `#25d366` styling already established on PriceListPage.
- Message templates live in `src/lib/` next to `priceListText.ts`, same style.

### Verification
- `npm run build` (tsc + vite) passes.
- Manual smoke test in dev: each button opens a correct `wa.me` URL; invalid phones (`abc`, `080`, empty) show the error toast; valid Nigerian formats (`08031234567`, `+234 803 123 4567`) normalize to `2348031234567`.

### Explicitly out of scope (Phase 2, future)
WhatsApp bot/webhook, server-side receipt PDFs, bidirectional sync, bulk overdue reminders.
